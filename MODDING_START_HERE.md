# MODDING_START_HERE — старт для нового разработчика и его ChatGPT

**Этот файл — входная дверь в создание дополнений DnD VTT, НЕ инструкция по сборке APK/EXE.** Основной клиент Unity находится в этой ветке, но новые JSON-моды обычно публикуются в других репозиториях и подхватываются мастерской без обновления приложения.

1. **DnD-VTT-Content** — [README](https://github.com/waitermisanthrope-creator/DnD-VTT-Content#readme) → [AGENTS.md](https://github.com/waitermisanthrope-creator/DnD-VTT-Content/blob/main/AGENTS.md) → [полное руководство автора и для ChatGPT](https://github.com/waitermisanthrope-creator/DnD-VTT-Content/blob/main/docs/MOD_AUTHOR_GUIDE.md) → [атлас КАЖДОГО файла Content](https://github.com/waitermisanthrope-creator/DnD-VTT-Content/blob/main/docs/FILE_ATLAS.md).
2. **DnD-VTT-Assets** — [README](https://github.com/waitermisanthrope-creator/DnD-VTT-Assets#readme) → [AGENTS.md](https://github.com/waitermisanthrope-creator/DnD-VTT-Assets/blob/main/AGENTS.md) → [атлас КАЖДОГО файла Assets](https://github.com/waitermisanthrope-creator/DnD-VTT-Assets/blob/main/docs/FILE_ATLAS.md).
3. **Основное приложение** — `PROJECT_ATLAS.md` и `PROJECT_ATLAS.txt` (атлас файлов и имён основного проекта), `AGENTS.md`, `unity/README.md` и **реальные** исходники ниже. Атлас бывает устаревшим: для действия используй текущие исходники/каталог и git diff.
4. **Контракт работающего клиента** — `unity/Assets/Vtt/Runtime/LegacySessionPanel.ContentManager.cs` (адреса и UI каталогов), `WorkshopStore.cs` (поддерживаемые поля, проверка SHA-256, безопасная установка, зависимости), `WorkshopRuntime.cs` (материалы и AssetBundle), `LegacySessionPanel.WorkshopLibrary.cs` (размещение объектов).

## Где что менять

| Цель автора | Репозиторий и путь | Требуется новый APK? |
|---|---|---|
| Новая/исправленная раса, класс, черта, предмет, крафт | `DnD-VTT-Content/packages/<id>.json` + `catalog/v3/index.json` | **Нет**, если JSON укладывается в существующие обработчики |
| Декларативная карта, цвет, простой примитив | `DnD-VTT-Assets/packages/<id>.json` + `catalog/v4/index.json` | **Нет**, если клиент поддерживает структуру |
| Загруженные обои/иконки, JPEG-превью | `DnD-VTT-Assets`, проверенные release assets + запись каталога | Обычно нет, в пределах поддержанного формата |
| Сложная/анимированная 3D-модель | Проверенный ресурс и платформенные AssetBundles | Требуются Unity-сборочные инструменты и QA; не обычный ручной JSON |
| Новая игровая механика / новый тип пакета | Unity C# в `experiment/unity-vtt` | **Да** (если нужен новый код клиента) |

Текущая Unity-ветка читает `https://raw.githubusercontent.com/waitermisanthrope-creator/DnD-VTT-Content/main/catalog/v3/index.json` и `https://raw.githubusercontent.com/waitermisanthrope-creator/DnD-VTT-Assets/main/catalog/v4/index.json`. Попадание в эти каталоги **публично** для пользователей данного канала. Текущая мастерская не читает обычные GitHub feature-ветки как отдельный приватный DEV-каталог.

## Тебе поручили «научить новичка делать моды»?

Тогда ChatGPT должен:
1. Сам прочитать из GitHub 2 README, 2 AGENTS, руководство и атласы выше, затем открыть **реальный** пример `packages/demo.race.lanternfolk.json` и схему `schemas/catalog-entry-v1.schema.json`.
2. Простыми словами объяснить человеку модель `пакет → запись в каталоге → кнопка скачать в мастерской → проверка/установка`. Объяснить разницу между **публичным** коммитом в main и черновиком в ветке.
3. Предложить маленькую первую задачу (например, свою расу), создать новый уникальный ID, валидный payload JSON и каталожную запись по существующему контракту.
4. Реально пересчитать byte length/SHA-256, проверить уникальность ID и URL, новую версию, допустимые поля, авторство/лицензию. Когда инструменты не дают запускать расчёт или писать в GitHub, честно показать точные команды и web-редактор, а не подделывать результат.
5. Если GitHub-инструмент поддерживает **запись**, вносить изменения с отчётом об SHA коммита. Само «подключение GitHub» может давать ИИ **только чтение**; обычный бесплатный чат не обещает полномочий Codex.
6. Помочь открыть в установленном приложении мастерскую, обновить каталог, скачать пакет, проверить действие на реальном Android/ПК и внести следующую ревизию после обратной связи.
7. Никаких паролей, GitHub PAT, ключей подписи, закрытых сохранений или стороннего непроверенного кода. Не выдавать неподдерживаемые «скриптовые способности» за реально работающую механику.
8. После создания нового файла **обновить атлас соответствующего репозитория**, чтобы следующий ИИ его находил.

## Полномочия команды

- **Доверенные администраторы**, которым предоставлен GitHub write, могут создавать, редактировать и публиковать пакеты **без дополнительных согласований** с владельцем. Распределение задач между ними не является программным запретом.
- **Модераторы** имеют ограниченные права через роли приложения/сервера. Роль внутри Unity/Supabase сама по себе не даёт GitHub write. Не выдавать недоверенным модераторам право коммитить в официальный каталог.
- Выпуск основных Unity APK/EXE сейчас остаётся отдельно от поставки JSON-модов. Не запускать Unity release workflow ради изменения расы.
- Автор обязан не скрывать фактическую публичность каталога, не присваивать чужое авторство и сохранять пользовательские данные/стабильные ID.
