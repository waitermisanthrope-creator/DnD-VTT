# Повседневная разработка Unity с Codex

Состояние проверки: 2026-10-25. Это инструкции процесса, не новый игровой модуль.

## Запуск

Открыть checkout ветки `experiment/unity-vtt`, рабочий каталог `unity/`.
Codex применяет корневой `AGENTS.md` и более близкий `unity/AGENTS.md` к Unity-файлам;
при старте из корня явно попросить прочитать Unity-инструкцию. Эта документация
читается по ссылке из инструкции; Skills должны быть доступны в текущем клиенте,
репозиторий не устанавливает Superpowers/Unity Plugin автоматически.

Пример простой задачи:

> Работай в experiment/unity-vtt, проект unity/. Прочитай unity/AGENTS.md.
> Исправь [наблюдаемый дефект], сохрани контракты данных. Один агент,
> целевые проверки после этапа; подготовь diff для ревью без публикации.

Пример сложной задачи:

> Прочитай unity/AGENTS.md. Запусти параллельно двух встроенных субагентов:
> Explorer — [модуль/архитектура], QA — [тесты/риски]. Только чтение,
> короткие отчёты с путями. Дождись обоих, проверь выводы, затем внеси
> минимальные изменения сам и выполни релевантные проверки. Без main/релиза.

Это описания задач встроенным субагентам, а не зарегистрированные custom agent IDs.
Применять нужные Superpowers по задаче, Unity Skills — по конкретной области
(например, ui/ui-imgui для существующего OnGUI); не загружать все Skills сразу.

## Выбор проверки

Из корня репозитория, выбирать только затронутые контракты:

```bash
python3 -B unity/ci/check_sheet_provenance.py
python3 -B unity/ci/test_update_settings_contract.py
python3 -B unity/ci/test_brand_visual_contract.py
python3 -B unity/ci/test_content_registry_contract.py
python3 -B unity/ci/test_character_preview_contract.py
python3 -B unity/ci/test_launcher_aliases.py
```

Для сохранений при доступном .NET 8:
`dotnet run --project unity/ci/workshop-tests -- --character-delete`.
Общий workshop-прогон требует проверенного каталога пакетов и пути репозитория;
точные аргументы см. в существующем CI, не запускать сетевую загрузку без нужды.
При изменениях сборочной безопасности — `python3 -B unity/ci/test_cloud_release.py`.

Unity-контракты: `./unity/verify.ps1 -Stage MigrationContracts` в Windows PowerShell
с доступным Editor версии из ProjectVersion.txt (при другом пути передать `-Editor`).
Скрипт использует Windows-specific Start-Process; Linux/pwsh недостаточно. Windows/Android сборки и runtime
проверять существующим процессом по `unity/README.md`, `unity/VALIDATION.md`,
`unity/verify.ps1` и актуальной CI-конфигурации. Эти ссылки не разрешают запуск
публикации. Setup/MigrationSetup изменяют сцены, это не read-only тесты.
Исторические README/планы сверять с кодом и текущим compact state.

Перед интеграцией важных изменений: полная релевантная регрессия, компиляция,
платформенные и runtime-проверки; изменения сохранений требуют обеих платформ,
roundtrip/restart/backup/неизвестных полей и отказа при конфликте ID. Сцены/ассеты
требуют проверки `.meta`, GUID, ссылок и просмотра результата. Для UI нужны реальные
кадры и взаимодействия; физический Android указывать отдельно от эмуляции/Wine.
Для документации достаточно проверки ссылок, области diff и конфликтов инструкций.

## Что проверено при внедрении

- Два встроенных субагента Explorer и QA запущены параллельно с изолированными
  промптами, только чтение; основной агент получил оба итоговых отчёта до правок.
- Explorer подтвердил существующий partial LegacySessionPanel, общий CharacterSheetStore,
  документы/карты и отдельный Unity build pipeline. QA подтвердил атомарные сохранения,
  `.bak`, опасность генераторов сцен и ограниченность source-contract проверок.
  Основной агент отдельно прочитал ключевые исходники/verify.ps1 и повторил проверки.
- Все шесть Python-команд выше выполнены повторно основным агентом: exit 0;
  provenance — 44 источника, launcher aliases — 2 теста, остальные — PASS-маркеры.
- Корневое уточнение исключает перенаправление Unity в WebView/main/release.
  Игровые исходники, сохранения, сцены, `.meta`, packages и GitHub Actions не изменялись.
- `codex-cli 0.163.0` доступен. Попытка отдельной новой read-only сессии через
  `codex exec --ephemeral --sandbox read-only -C .../unity` завершилась до старта:
  `failed to initialize in-process app-server client: Read-only file system (os error 30)`.
  Поэтому автоматическое чтение инструкций новой сессией фактически не подтверждено.
  Для повторения: открыть новую задачу Codex в unity/ и попросить назвать загруженные
  инструкции, разрешённую ветку, правила сохранений и лимит субагентов без изменений.

Итоговое read-only ревью QA: блокирующих конфликтов инструкций не найдено;
уточнено требование Windows для verify.ps1. QA не подтверждает исполнение
команд основного агента: их результаты проверены основным агентом по выводу.

## Границы Cloud

Поддержка проектных custom agents в текущем Codex Cloud **не подтверждена**.
Запрос официальной документации через веб-инструмент вернул ошибку;
HTTPS-запрос к `https://developers.openai.com/codex/subagents` не смог подключиться
к настроенному прокси. Наличие CLI и команды agents само по себе не доказывает
Cloud discovery `.codex/agents/`, схему TOML или применение read-only ролей.
Поэтому `.codex/agents/` и конфигурация ролей не создавались. Встроенная делегация
проверена в этой сессии; её наличие в других клиентах нужно проверять отдельно.

Unity Editor/Unity CLI/PowerShell/dotnet не обнаружены через PATH в этой среде;
Unity-сборки, C# runtime-прогоны, native UI и Android-device QA здесь не выполнялись.
Наличие bootstrap SDK вне PATH не является доказательством успешного теста.
Cloud status не подтвердил Unity license/CI credentials. Не устанавливались сервисы,
не читались секреты и не запускались Actions, релизы, merge или push.
