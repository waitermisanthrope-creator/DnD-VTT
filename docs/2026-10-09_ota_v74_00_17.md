# V74.00.17 — единый процесс OTA


### Причина бага и исправление
На видео старая версия, но причина сохранилась в исходниках: index.html загружает
update_manager_v2.js перед Settings.js; Settings.js затем присваивал новый
DND_UPDATE_UI. Его check выполнял только checkAndStage, открывал runSceneTest
(псевдопрогресс, version 70.34.1, текст «файлы не скачиваются») и оставлял реальную
установку отдельной кнопке в настройках. Удалён этот дублирующий контроллер.

Manager владеет единой runUpdate: inspect → scene → stage → applyStaged → finish.
Автоматический старт один раз на dnd:splash-complete либо сразу, если заставка
уже закончена. Убраны прежний запуск через таймер 900 мс и повторные автопроверки
при каждом showCharacterSelect; badge не запрашивает сеть до окончания заставки.
Logo имеет fallback 650 мс на случай отсутствующего transitionend, завершение
защищено от повторного вызова и событий перехода дочерних элементов.

Все реальные входы обновления используют один Promise. Успешная установка
заблокирована от повторного запуска до native recreate; demo нельзя запускать
поверх реального обновления. Inspect не вызывается вторично перед stage.
Progress callback привязан к id native request, не одному глобальному callback.
Сцена использует bytesDone/bytesTotal, если доступны; номер текущего файла
больше не заставляет прогресс преждевременно дойти до 100%. При download/verify
0–90%, при apply 90–99%, успешный apply переводит сразу в 100%. Нет таймеров,
которые искусственно завершают реальную загрузку; smoothing лишь следует данным.
Ошибка stage не вызывает apply. Ошибка stage/apply видна в той же сцене; доступны
«Повторить» и «Закрыть». Нет обновления — обычное приложение без этой сцены.
Offline startup не блокирует приложение, ручная проверка/повтор доступны.
Web без native installer не скачивает весь пакет и не объявляет установку успешной.
Native Java/rollback/атомарное переключение версий не изменены; это исправление
доставляется как OTA. Установленная до релиза старая JS-версия получит исправление
только после установки V74.00.17 старым способом или через новый APK.

### Телефонный сценарий после установки V74.00.17
Когда появится следующая версия: запустить приложение, дождаться/пропустить
логотип; без входа в настройки должна появиться сцена реального скачивания,
затем установки, после успешного применения — перезапуск. Переоткрывать настройки
и нажимать «Установить» больше не нужно. На актуальной версии сцена не появляется.

Первое обновление до V74.00.17 устанавливается старым способом; новая автоматизация действует после установки исправленных JS assets.
