# V74.00.15 — реестр настоящих MakeHuman-морфов, 2026-10-09

## Принятое состояние
Пользователь подтвердил на телефоне работу текстуры V74.00.14 («Отлично,
заработало!») и видимую работу ползунков («вроде работают»). Это подтверждение
текстуры и прежних процедурных пропорций; новые морфы V74.00.15 ещё требуют
проверки на телефоне. Продолжение с общим реестром морфов разрешено.

## Что подключено
- shoulders / Плечи: measure-shoulder-dist-{incr,decr}.
- chest / Грудь: measure-bust-circ-{incr,decr}.
- waist / Талия: measure-waist-circ-{incr,decr}.
- hips / Бёдра: measure-hips-circ-{incr,decr}.
- Каждый ползунок [-1,1] выбирает положительный или отрицательный именованный
  target; ноль возвращает исходную геометрию. Все каналы складываются до skinning.
- height, width, muscle, fat, arms, legs, head остаются процедурными. Это не
  полный MakeHuman macro stack. Женская/мужская кожа по-прежнему меняет текстуру.
- Остальной рендерер общий. Риг 53 joints, геометрия/индексы/UV и исходный
  human-base-rigged.glb сохранены. Оригинал нужен для аудита и будущих переносов.
- Runtime читает общий реестр из glTF extras.dndMorphChannels. Формат правила:
  {positive: 'target-name', negative: 'target-name', scale: 1}. Новый параметр
  добавляется в JSON реестра генератора и AXES, без отдельной реализации рендера.
  Именованный target с названием оси также поддерживается. Неполная пара или
  неверная длина дельт не отключают процедурный fallback.
- Node weights имеют приоритет над mesh weights. Rigid morphs применяются в
  локальных координатах перед матрицей узла; skinned morphs — перед костями.
- Убрано повторное масштабирование тела в матрице камеры, процедурное изменение
  отключено только для осей с настоящими targets. Масштаб камеры фиксируется по
  нейтральному телу, поэтому изменение роста видно. Процедурная геометрия считается
  один раз за draw. Матрицы костей считаются один раз на часть, а не на вершину.
- Значения output у восстановленных ползунков соответствуют сохранённому состоянию.

## Перенос исходных данных
Источник: https://github.com/makehumancommunity/mpfb2, commit
`d0a32e57a7f915cb2f2b95410e2117648c7bbb7e`. Core assets CC0; текст лицензии
сохранён в app/assets/3d/makehuman/LICENSE.ASSETS.md. SHA256 base.obj и восьми
source targets записаны в extras.dndMorphSource производного GLB.

Старый closest-surface тест переносил через bbox и не обеспечивал правильное
соответствие областей. Новый tools/build_makehuman_morphs.js строит один общий
barycentric map по UV body (без helper/joint геометрии), повторно использует его
для всех targets и учитывает V-flip glTF. OBJ и target-файлы в native MakeHuman
Y-up; Blender-перестановку X/-Z/Y из старого readTarget здесь применять нельзя.
Дельты переводятся из decimeter units в meter units коэффициентом 0.1.

70985/70985 вершин сопоставлены. 897 точек требуют минимального прижатия весов
на UV-границах; максимальный barycentric outside 0.00053863. Допуск генератора
0.001, несовместимая UV останавливает сборку. Максимальное расхождение дельт у
дублированных вершин UV-шва: 0.0000015 m (~0.0015 mm), проверено тестом.
Результат UV-интерполяции приближённый: экспортированная поверхность subdivided и
слегка отличается от hm08. Не выдавать это за точное совпадение исходных mesh IDs.

Генератор пока намеренно поддерживает одну body primitive; сложные GLB отклоняются,
а не получают target с неверным count. Источник и файл назначения должны различаться.

Воспроизведение (нужны данные MPFB, не огромный пользовательский архив):
```
MAKEHUMAN_SOURCE_COMMIT=d0a32e57a7f915cb2f2b95410e2117648c7bbb7e \
node tools/build_makehuman_morphs.js /path/to/mpfb/data human-base-rigged.glb \
  app/assets/3d/makehuman/human-body-morphs.glb
```
Реестр: tools/makehuman_morph_channels.json. Производная модель ~11.81 MB,
расположена под app/, загружается относительным URL и входит в APK и OTA.
