## Контракт и проверка

`unity/Tools/sync_character_sheet.cjs` исполняет текущие локальные исходники main в Node VM без сети: генерирует 60 JS эталонов (уровни 1–20 × владение 0/1/2; в том числе мультикласс), конфигурацию навыков, 402 записи каталога заклинаний и provenance. Скрипт отказывается работать в другой ветке или при расхождении используемых исходников с main.

`CharacterSheetValidation.Validate` сравнивает C# с эталонами, проверяет изменение single/array/wrapper, изоляцию второго героя, сохранение неизвестных полей/вложенных предметов/состояний класса/старого HP, отказ при смене ID/будущей схеме, запись/перезагрузку/резервную копию. Вызывается также перед обоими migration builds. Это проверка базовых формул, а не всех правил main.

Локальный файл Unity: `Application.persistentDataPath/dnd_multi_characters_v2.json`. Запись только кнопкой **Сохранить на этом устройстве**; `*.pending` заменяет основной файл атомарно, предыдущий остаётся в `*.bak`. Старые браузерные/Electron/WebView данные и Supabase не записываются. До сохранения доступен экспорт изменённого архива; исходный импорт остаётся отдельно доступен без изменений. Не подключать live cloud до реализации протокола CAS и контрактных тестов.

Продолжение: сначала полноценные операции листа и справочники (создание/уровень/расы/инвентарь/заметки/дайсы), затем классовые команды с исходными pending/source/resource контрактами и fixtures. Карту не выдавать за завершение листа. Статус всего переноса остаётся **НЕ ВЫПОЛНЕНО**.
