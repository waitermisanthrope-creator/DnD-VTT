# Стабильность UI и ремёсла — кандидат Unity 1.00.51

**Исторический тестовый кандидат: APK/Windows сборки успешны, но Windows UI QA обнаружил регрессию общего скина. Заменяется кандидатом1.00.52. Не считать стабильным.**

Рабочая ветка: `experiment/unity-vtt`. Основа: опубликованная 1.00.50 (`c2011273`). `main`, публичный канал обновлений, approval-файлы и опубликованные APK не изменялись. Эта версия — тестовый кандидат, не публичное обновление.

## Изменения

- Устранён общий путь разрушения UI после resume: старые GUIStyle сохраняли ссылки на уничтоженные фоны. Resume восстанавливает загрузку общих читаемых текстур без уничтожения ссылок; настоящая смена темы сбрасывает все кэши стилей единым типизированным методом.
- Возвращены горизонтальное перелистывание и плавная фиксация через существующий MenuGesture и единственный requestedSheetTab. Сохраняется арбитраж вертикальных списков, вложенных горизонтальных областей и нативных полей. Жест отменяется при паузе/потере фокуса/мультитаче.
- Дайсы сохраняют один ограниченный по времени стол. Первое создание отложено для реакции интерфейса; повторное открытие переиспользует сцену. Каталог внешнего вида/текстуры читаются в фоне, посторонние базы предметов не загружаются. Уже начатый скрытый бросок завершается без рендера, затем физика останавливается; есть TTL/lowMemory/destroy освобождение.
- Инвентарь отделён от ремёсел. Кошелёк, рынок, предметы, справочники и вес остаются. Управление контейнерами скрыто; явный перенос сохраняет оригинальные записи, резервную копию всего архива, неизвестные свойства, варианты предметов и идентификатор успешного переноса. Повторный перенос ничего не добавляет.
- Страница «Ремёсла» находится между инвентарём и заметками; прежние ID страниц сохранены. Добавлены режимы, профессии, книга/поиск/избранное, проекты, часы работы, ручной итог, журнал, отмена и архив. Списки ограничены страницами; каталог загружается по необходимости.
- Автоматические и полуавтоматические операции проверяют актуальные материалы, инструменты, условия, стоимость, версию рецепта и сохраняют расход/результат атомарно. Полуавтомат ждёт локального мастера. Ручной режим применяет только явно выбранные изменения.
- Развитие профессий выключено по умолчанию. Опциональные уровни, опыт, требования, модификаторы, открытие рецептов и производственные цепочки задаются данными. Прежние Craft/Mix/Research сохранены через адаптер проектов.
- Homebrew JSON использует существующий WorkshopStore: ID, версии, зависимости, контроль целостности, установленный контент и удаление. Предметы не дублируются внутри рецептов. Исполняемый пользовательский код не поддерживается. Есть примеры двух зависимых пакетов и документация формата.

## Известные ограничения и незавершённые проверки

1. Нет физического Android-устройства. Пять циклов настоящего сворачивания/возврата, блокировка экрана, touch-свайпы и производительность телефона не выполнены. Шесть simulated callbacks в нативном smoke не заменяют эти проверки.
2. Удалённое одобрение мастера и авторитетные ограничения сетевой кампании не реализованы: текущий Unity-клиент не имеет транспорта/полномочий кампаний. Локальная передача устройства явно обозначена как доверенный офлайн-режим. Cloud admin не используется как мастер.
3. Правила2014/2024/Homebrew выбираются декларативно; это не заявление о наличии всех официальных рецептов обеих редакций. Книга использует установленные сборники и импортированные рецепты. Примеры Homebrew не устанавливаются и не публикуются автоматически.
4. Готовность к реальным сессиям нельзя подтверждать одной компиляцией. До окончательной приёмки нужны физические Android-проверки и результаты нативного CI ниже.
