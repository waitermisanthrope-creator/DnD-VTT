# [НЕ ВЫПОЛНЕНО] Мастерская1.00.38 — серверное подключение ожидает SQL Editor

Клиент: главная лента новых/обновлённых модов, отдельная страница всех15 сборников, сортировка по общему рейтингу, фильтр личного избранного. Сердечко одновременно означает голос и избранное. Обновление рейтинга/нажатие сердечка сохраняет текущую страницу; изменение фильтра или сортировки открывает первую страницу, сокращение результатов ограничивает номер страницы допустимым диапазоном. Первое нажатие добавляет, второе снимает; рейтинг — число разных аккаунтов. Гостям доступно чтение количества, кнопка изменения отключена, сервер также запрещает запись гостям.

## Включение на рабочем сервере

У этой среды нет административного доступа к Supabase и сетевого разрешения для проекта. Сборка APK не выполняет миграцию БД. Рейтинг в рабочем проекте пока НЕ подтверждён.

1. В существующем проекте Supabase `rrjqxbfgwsjhgshajnob` откройте SQL Editor.
2. Выполните **целиком только новый файл** [202610230001_workshop_hearts.sql](../../supabase/migrations/202610230001_workshop_hearts.sql). Предыдущие миграции Auth/access/moderation уже должны быть установлены; не запускайте их заново и не меняйте ключи. Этот файл повторно применим: голоса и статус отключённых модов сохраняются.
3. Проверьте чтением:

```sql
select to_regprocedure('public.read_workshop_hearts(text[])') is not null as read_ready,
       to_regprocedure('public.set_workshop_heart(text,boolean)') is not null as write_ready;
select has_function_privilege('anon','public.read_workshop_hearts(text[])','EXECUTE') as guest_can_read,
       has_function_privilege('anon','public.set_workshop_heart(text,boolean)','EXECUTE') as guest_can_write;
select public.read_workshop_hearts(array['dnd.collections.weapons','dnd.race.aasimar']);
```

Ожидается `true/true`, затем `true/false`. В SQL Editor без JWT пользователя личное `hearted=false`; рейтинг возвращается общий. В клиенте обновите рейтинг. Под своим аккаунтом поставьте сердечко, включите «Только избранное», снимите сердечко: карточка исчезнет, счётчик уменьшится на1. Проверьте второй аккаунт/устройство: счётчик общий, собственное избранное раздельное. После выхода избранное очищается из памяти. Гость не может поставить сердечко.

Никаких паролей или административных ключей вводить в Unity и передавать в чат не нужно.

## Данные и отказоустойчивость

Реестр содержит все417 текущих ID из Content v3 /Assets v9. Серверные таблицы закрыты от anon/authenticated; узкие security-definer функции используют существующий Auth/center_guard, учитывают блокировку аккаунта и не принимают чужой user_id. Пара `(mod_id,user_id)` уникальна. Сервер получает явное намерение поставить/снять: повтор потерянного запроса безопасен. По одному моду записи сериализованы транзакционной блокировкой. Обновление версии сохраняет рейтинг того же ID. Удаление аккаунта удаляет его голос через FK cascade.

В ответе нет списка голосовавших, UUID, почт или дат голосов. Гость видит только общие количества; пользователь — общие количества и собственные флаги. Неизвестный/отключённый ID не принимает голоса. Новые опубликованные ID добавляет доверенный оператор: `insert into app_private.workshop_mods(id) values ('new.id') on conflict do nothing;`.

Клиент читает снимок пакетами по200 ID (лимит сервера500), применяет его только после полного чтения, не создаёт локальные фиктивные оценки. При неопределённом результате записи требуется повторное чтение; до него изменение отключено. Выход/смена аккаунта сбрасывает личное состояние и игнорирует запоздалые ответы. Запоздалое обновление токена после выхода не восстанавливает сессию.

`publishedAt`/`updatedAt` восстановлены по полной истории публичных каталогов, не по времени текущего обновления. Сборники учитывают дату входящих модов. При входе мастерская раз в сессию обновляет каталоги; кеш и установленные пакеты остаются доступны при отсутствии сети. Старые версии клиентов допускают новые необязательные поля. Все397 payload и20 метаданных, ID, версии и SHA сохранены.
