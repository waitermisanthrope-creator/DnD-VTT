## [НЕ ВЫПОЛНЕНО] UX40-01 — Не терять владения при совпадении выборов

**Воспроизведение:** человек (стандартный), воин, предыстория «Солдат»; в двух классовых навыках выбрать Athletics и Intimidation, закончить создание. Предыстория уже выдаёт те же навыки. Создание успешно; `skillsData` содержит только `athletics:1` и `intimidation:1`, `pendingChoices=[]`. Два отдельных выбора не дали дополнительных владений и не оставили запроса на замену.

**Доказательства:** [выборы](audit-1.00.40/06-create-skills.png), [подтверждение](audit-1.00.40/07-create-review.png), JSON. Кадр выбора снят до завершающих кликов; окончательный ответ записан в `choiceState`. `CharacterCreation.cs`, метод `Create`: seed предыстории объединяется до применения ответов, затем владение просто присваивается повторно.

**План/готово когда:** учитывать уже выданные владения и пересечения между источниками; предложить допустимую замену по применяемым правилам. Для этого сценария — четыре разных навыка либо явное незавершённое решение с объяснением. Проверить также повторные языки/инструменты (отдельно ещё не воспроизводились). Не переписывать молча старые профили и не менять утверждённые правила ради обхода ошибки.

## [НЕ ВЫПОЛНЕНО] UX40-03 — Один согласованный уровень и повышение уровня

## [НЕ ВЫПОЛНЕНО] UX40-04 — Осмысленная точка восстановления при автосохранении

**Воспроизведение:** переименовать `Audit Fighter` в `Undo Probe`, проверить архив и автоматический `.bak`. Текущий файл содержит `Undo Probe`, резервный — `Undo Prob`. Автосохранение на каждом символе заменяет предыдущую резервную копию; возврат последней операции фактически возвращает предыдущую букву.

**Доказательства:** [переименование](audit-1.00.40/12-name-undo-probe.png), JSON `current`/`previousAutomaticBackup`; `CharacterSheetRules.cs`, `CharacterSheetStore.Save`, атомарный `File.Replace(..., path+'.bak')` после каждого изменения листа.

**План/готово когда:** сохранить надёжное автосохранение, но отделить его технический backup от пользовательской точки восстановления. Рассмотреть историю/снимок перед операцией или объединение серии правок с ограниченной задержкой и обязательным сбросом при выходе. Проверить имя, числа, удаление и импорт, сбой записи и восстановление. UI ясно сообщает дату/состав восстанавливаемого снимка. Независимая ручная резервная копия уже существует; её исправность этим наблюдением не опровергается.

**Доказательства:** [до](audit-1.00.40/27-abilities.png), [после](audit-1.00.40/28-spell-stat.png), JSON; `LegacySessionPanel.Sheet.cs`, ветка способностей передаёт свободный текст в `CharacterSheetRules.Modifier`, который обращается к ключам характеристик с учётом регистра.

**Доказательства:** [круг −1](audit-1.00.40/31-negative-spell-level.png), [максимум HP −5](audit-1.00.40/36-negative-hp.png), JSON. **План/готово когда:** проверки по назначению поля: круг 0–9, допустимые HP и согласованные текущие/максимальные/временные HP по игровым правилам. ## [НЕ ВЫПОЛНЕНО] UX40-21 / P1 — Не сливать разные свои предметы с потерей свойств

**Воспроизведение:** в категории «Хлам» добавить свой `Stack Probe`, вес1кг; затем добавить ещё один `Stack Probe`, вес2кг. Вместо разных записей приложение оставляет одну: `weight='1 кг'`, `count=2`. Вес2кг второго предмета исчезает; эта стопка считается как2кг вместо суммарных3кг.

**План/готово когда:** определить идентичность и условия совместимой стопки; свои разные предметы получают устойчивую идентичность либо проверку всех значимых свойств до слияния. Проверить одинаковые имена с разными весом/описанием/параметрами, одинаковые предметы, импорт, извлечение из контейнера и сохранение/перезапуск.
