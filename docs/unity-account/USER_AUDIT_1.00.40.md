## Что действительно проверено

Запущен опубликованный Windows payload версии 1.00.40, извлечённый из официального NSIS-установщика, без изменения игровых бинарников. Исходник выпуска `5fa7dce78f63f32eaa40d525ffffd68ed17d6f9a`; SHA256 установщика `d253d05dec8a27b531a1546c6b7664d4dedb94355cf605d3708f5b3f2eaed613`.

Среда: Linux, Wine 10, Xvfb, программный D3D11, окно 1280×800. Это интерактивный запуск настоящего приложения с мышью, клавиатурой, прокруткой и чтением сохранений. Это **не новый прогон установки на Windows и не физический Android-тест**. Использованы отдельный Wine-префикс и отдельный архив с вымышленным героем; пользовательские сохранения не затрагивались.

Пройден маршрут: пустой архив → создание → ошибка пустого имени → раса/класс/предыстория → характеристики/язык/навыки → подтверждение → сохранённый лист → изменение класса/уровня/имени → список героев → повторный запуск. Проверены текущий JSON и автоматический `.bak`. Исходники сопоставлены с наблюдениями. Скриншоты — реальные кадры приложения, без дорисовки; сокращённый [JSON доказательств](audit-1.00.40/synthetic-profile-evidence.json) содержит только синтетические данные.

**Итого:** 7 новых воспроизведённых проблем (UX40-01–07), 3 известных незакрытых ограничения (08–10), 3 задачи дополнительной проверки (11–13). P1 — неверные игровые данные; P2 — повседневные неудобства/ограничения; P3 — оформление. Приоритеты действуют внутри текущего блока, не меняют утверждённую глобальную очередь.

## [НЕ ВЫПОЛНЕНО] UX40-01 — Не терять владения при совпадении выборов

**Воспроизведение:** человек (стандартный), воин, предыстория «Солдат»; в двух классовых навыках выбрать Athletics и Intimidation, закончить создание. Предыстория уже выдаёт те же навыки. Создание успешно; `skillsData` содержит только `athletics:1` и `intimidation:1`, `pendingChoices=[]`. Два отдельных выбора не дали дополнительных владений и не оставили запроса на замену.

**Доказательства:** [выборы](audit-1.00.40/06-create-skills.png), [подтверждение](audit-1.00.40/07-create-review.png), JSON. Кадр выбора снят до завершающих кликов; окончательный ответ записан в `choiceState`. `CharacterCreation.cs`, метод `Create`: seed предыстории объединяется до применения ответов, затем владение просто присваивается повторно.

**План/готово когда:** учитывать уже выданные владения и пересечения между источниками; предложить допустимую замену по применяемым правилам. Для этого сценария — четыре разных навыка либо явное незавершённое решение с объяснением. Проверить также повторные языки/инструменты (отдельно ещё не воспроизводились). Не переписывать молча старые профили и не менять утверждённые правила ради обхода ошибки.

## [НЕ ВЫПОЛНЕНО] UX40-02 — Согласовать класс героя и его отображение

**Воспроизведение:** открыть созданного воина, в поле «Класс» набрать `Wizard Audit`. Автосохранение пишет `class`/`className` с новым значением, но `classId='fighter'`, `classes[0].name='Воин'` и классовые данные остаются прежними. В списке герой уже представлен как Wizard Audit.

**Доказательства:** [поле класса](audit-1.00.40/09-class-label-edit.png), [список](audit-1.00.40/13-roster-level-mismatch.png), JSON; `LegacySessionPanel.Sheet.cs`, метод `Hero`. Поля расы и предыстории тоже свободно редактируются в коде; последствия их изменения требуют отдельной проверки.

**План/готово когда:** однозначно разделить косметическую подпись и смену игровой сущности. Настоящую смену класса проводить через согласованный переход с проверкой ресурсов/уровней/способностей, либо показывать игровую идентичность как неизменяемое поле до готовности такого перехода. Импортированные старые имена/ID сохранять совместимыми. После правки UI, архив и расчёты описывают одного и того же героя.

## [НЕ ВЫПОЛНЕНО] UX40-03 — Один согласованный уровень и повышение уровня

**Воспроизведение:** в поле «Уровень» поставить 5, вернуться к списку героев. Сохраняется `level=5`, но `classes[0].level=1`, `profBonus=2`; список показывает «1 ур.». `CharacterSheetRules.Level` суммирует `classes`, поэтому расчёты используют первый уровень.

**Доказательства:** [лист с уровнем 5](audit-1.00.40/11-level-edit.png), [список с уровнем 1](audit-1.00.40/13-roster-level-mismatch.png), JSON; методы `Hero`, `CharacterSheetRules.Level`, `Proficiency`, `Recalculate`.

**План/готово когда:** определить канонический уровень на основе классов, общий уровень показывать согласованно; повышение проводить с выбором класса и обязательных решений, а не независимым числом. Проверить обычного героя и мультикласс, импорт старых форматов, пересчёт мастерства (для суммарного 5 уровня +3), сохранение/повторное открытие. Не выдавать автоматически HP и способности без соответствующих решений.

## [НЕ ВЫПОЛНЕНО] UX40-04 — Осмысленная точка восстановления при автосохранении

**Воспроизведение:** переименовать `Audit Fighter` в `Undo Probe`, проверить архив и автоматический `.bak`. Текущий файл содержит `Undo Probe`, резервный — `Undo Prob`. Автосохранение на каждом символе заменяет предыдущую резервную копию; возврат последней операции фактически возвращает предыдущую букву.

**Доказательства:** [переименование](audit-1.00.40/12-name-undo-probe.png), JSON `current`/`previousAutomaticBackup`; `CharacterSheetRules.cs`, `CharacterSheetStore.Save`, атомарный `File.Replace(..., path+'.bak')` после каждого изменения листа.

**План/готово когда:** сохранить надёжное автосохранение, но отделить его технический backup от пользовательской точки восстановления. Рассмотреть историю/снимок перед операцией или объединение серии правок с ограниченной задержкой и обязательным сбросом при выходе. Проверить имя, числа, удаление и импорт, сбой записи и восстановление. UI ясно сообщает дату/состав восстанавливаемого снимка. Независимая ручная резервная копия уже существует; её исправность этим наблюдением не опровергается.

## [НЕ ВЫПОЛНЕНО] UX40-06 — Упростить длинную форму создания

**Наблюдение:** характеристики, длинный вертикальный список языков и навыки находятся на одном шаге; кнопки перехода в конце. Для выбора языка и навыков нужна многократная прокрутка даже в 1280×800. **План/готово когда:** компактные группы/поиск, видимый счётчик N/M и уже выданные владения, заметные состояния выбора и ошибки рядом с группой, доступные действия перехода. Проверить короткий/длинный каталог, клавиатуру и телефон, не потерять сделанные ответы при прокрутке и возврате.

## [НЕ ВЫПОЛНЕНО] UX40-08 — Довести стартовую комплектацию до игрового героя

У созданного воина инвентарь пустой; отдельного выбора стартового набора на пройденном маршруте нет. См. **План/готово когда:** подзадача существующих целей 01/04: по очереди классов реализовать стартовые альтернативы, применение предметов/владений/способностей и все обязательные решения. После создания понятен список оставшегося, нет ложного статуса «полностью готов к игре». Не закрывать весь перенос классов по одному воину.

## [НЕ ВЫПОЛНЕНО] UX40-09 — Дружелюбный конфликт при импорте одного ID

**Известное ограничение:** другой вариант того же героя безопасно отклоняется. Основание — [отчёт 1.00.40](CHARACTER_FILES_1.00.40.md); в данном интерактивном проходе конфликт повторно не проверялся.

**План/готово когда:** показать сравнение и понятные варианты «оставить», «заменить с резервной копией», «создать отдельную копию»; ни один вариант не уничтожает остальных героев. Проверить одинаковый ID с одинаковыми/разными данными, несколько конфликтов, отмену и ошибку записи, повторный экспорт/импорт.

## [НЕ ВЫПОЛНЕНО] UX40-10 — Версия в портретном заголовке

**Известное ограничение:** короткая версия частично выходит за край; зафиксировано в [отчёте 1.00.40](CHARACTER_FILES_1.00.40.md) с нативными Windows-кадрами портретного сценария. Этот проход не добавляет подтверждения на телефоне.

**План/готово когда:** версия целиком видна либо доступна на понятном экране сведений; проверить узкие ширины, длинное имя и масштаб текста. Горизонтальная прокрутка вкладок листа предусмотрена специально и сама по себе багом не считается.

## [НЕ ВЫПОЛНЕНО] UX40-11 — Физический Android: файлы и обмен

## [НЕ ВЫПОЛНЕНО] UX40-12 — Проверить фон и финальное имя окна

**Наблюдение/гипотеза:** в запуске Wine фон меню чёрный; X11-окно называется `DnD VTT Unity Prototype`. Причина отсутствия рисунка не установлена. В исходниках оригинальные изображения есть и в Resources, и в StreamingAssets; нельзя объявлять, что Windows-ассеты отсутствуют только из-за Android-only fallback.

**План/готово когда:** повторить на нативной Windows и сравнить с ожидаемым оформлением, проверить загрузку Resources, выбор оформления и прозрачность слоёв. Если фон намеренно чёрный — закрыть как не-дефект с объяснением. Проверить пользовательское имя окна на Windows; убрать Prototype только если оно действительно видно в целевом клиенте и это соответствует именованию продукта. Оригинальные рисунки, package/signing identity и сохранения не заменять.

## Ограничения среды и исключённые ложные выводы

- В Wine встречалась ошибка TLS `Curl error 60`; это не доказательство ошибки сертификатов приложения на Windows/Android. TLS-проверки не отключались.
- Ошибки отсутствия аудиоустройства относятся к среде без звука, пока не воспроизведены на целевой платформе.
- Изменение размера X11-окна напрямую давало обрезанный viewport. Кадры этого опыта не включены в продуктовые доказательства: нужен штатный resize на Windows либо запуск с корректным разрешением.
- Проверки предыдущих выпусков не выдаются за вновь выполненные. Старые профили не мигрировались, реальный телефон и аккаунт пользователя не использовались.
