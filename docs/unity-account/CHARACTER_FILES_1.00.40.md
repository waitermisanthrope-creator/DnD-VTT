# [ВЫПОЛНЕНО] Unity 1.00.40 — файлы персонажей и подписи меню

Владелец поручил следующий блок после 1.00.39: исправить обрезанные подписи и сделать удобный обмен файлами персонажей. Работа ведётся в `experiment/unity-vtt`.

## Изменения

- Высота и ширина второстепенной навигации, кнопок над листом и возврата из технического центра обновлений вычисляются по реальному стилю текста. Телефонная навигация занимает одну компактную строку; остальные разделы доступны через главную. Подписи не разрываются посреди слова.
- Windows открывает системные диалоги «Открыть» и «Сохранить». Поддерживаются пути с кириллицей; отмена не меняет архив.
- Android использует системные `OPEN_DOCUMENT` / `CREATE_DOCUMENT` и отдельную закрытую Activity. Данные копируются в рабочем потоке; в Unity возвращается короткий результат с ID запроса, а не большой JSON через Intent/JNI. При закрытии ожидающей Activity запрос отменяется. Широкие разрешения на файловое хранилище не добавляются.
- Android «Поделиться JSON» использует прежний read-only ContentProvider и отдельный приватный каталог. Системное меню получателя открывается только по кнопке пользователя.
- Работа с файлами доступна из импорта, данных/резервных копий и листа. Маршруты через буфер обмена сохранены.
- Файлы проходят проверку размера до 1 МиБ, строгого UTF-8, BOM, структуры и версии архива. Используются прежние добавляющий импорт, защита конфликтующих ID и атомарное сохранение. Новых схем персонажа или параллельных хранилищ нет.

## Проверки

Локально: 56 проверок поведения и 63 проверки синтаксиса C# прошли. В том числе Unicode-пути, повторный импорт, перезапись с резервом, BOM, повреждённый JSON/UTF-8, слишком большой файл, неподдерживаемая схема и отсутствие побочных записей при отказе. Windows-ветка файлового кода скомпилирована отдельно; размер и семь смещений полей `OPENFILENAMEW` сверены с ABI x64. Java-мост скомпилирован JDK 21 против настоящего Android SDK 36; для локальной проверки использована только заглушка сигнатуры UnitySendMessage. Нативная сборка использует настоящий Unity Player.

В существующую проверку установленного Windows-приложения включены реальные системные диалоги открытия/сохранения с автоматической отменой, файловый экспорт/импорт с сохранением неизвестных полей, замер фактических границ подписей и 16 GPU-кадров. Три портретных кадра должны иметь действительно портретный viewport; логическая ширина 440 имитирует мобильную раскладку. Это не проверка физического телефона.

Дополнительная проверка реального APK требует закрытой Activity документов и отсутствия широких разрешений хранилища. Прежние нативные проверки листа, создания, миграции, мастерской, человека и дайсов сохранены.
