# Глобальный чат: подключение ников

Клиент 1.00.21 использует существующий Supabase Auth. Ник задаётся в Настройки → Ник в глобальном чате → Сохранить ник аккаунта. Допустимы 3–24 буквы (латиница/кириллица), цифры, пробел, `_`, `-`. Ники не уникальны, не являются ролями и не подтверждают личность администратора. Права по-прежнему проверяются по auth.uid() сервером.

## Одно действие владельца

В SQL Editor того же проекта rrjqxbfgwsjhgshajnob выполнить **целиком** файл [202610220001_chat_nicknames.sql](../../supabase/migrations/202610220001_chat_nicknames.sql). Он заменяет только существующую функцию чтения чата, добавляя безопасное отображаемое имя из метаданных аккаунта. Таблицы персонажей, staff, MFA, ключи и сообщения не удаляются. Миграция повторно применима.

Проверка установки из SQL Editor (чтение):

```sql
select position('nicknamesSupported' in pg_get_functiondef('public.read_chat()'::regprocedure)) > 0 as nicknames_ready;
```

Ожидается true. Затем в приложении войти в аккаунт, сохранить ник и обновить глобальный чат. Второй авторизованный аккаунт должен увидеть этот ник. При смене ника меняются подписи ещё не истёкших сообщений этого аккаунта. Срок жизни сообщений остаётся один час.

Без миграции: регистрация, вход, сохранение ника через Auth и старый чат доступны; отображение ников других игроков ещё не подключено, приложение это сообщает. Секреты для выполнения миграции в приложение не вводить.

## Что проверено автоматически

PostgreSQL WASM: прежние проверки входа/бана/мута/срока жизни/повтора запросов плюс серверное чтение ника, отсутствие утечки метаданных и отклонение HTML в имени. Это не проверка подключения к production Supabase. C#: валидация кириллицы, обрезка пробелов, отклонение HTML/email/переводов строк и неверной длины. Телефон и два реальных аккаунта требуют ручной проверки.
