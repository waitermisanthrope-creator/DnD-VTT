# Этап 1: фундамент оформления — 12.11.2026

## Реализация

Расширена существующая IMGUI-система, без смены UI-фреймворка. В настройках «Визуальные → Цвет интерфейса» доступны старое золото, бордовый, изумрудный, стальной синий, фиолетовый, нейтральный светлый и поле RGB HEX (`#RRGGBB`, также без `#`). Значения пресетов — технические исходные значения, централизованы в `UiTheme`; финальная художественная палитра не разрабатывалась.

Выбор пресета или применение корректного HEX сохраняет только акцент и действует при следующем событии IMGUI, без перезапуска. Остальные несохранённые настройки остаются черновиком. Ошибка записи показывает сообщение и сохраняет прежний активный цвет. Частичный/ошибочный HEX не применяется. Сброс удаляет переопределение и возвращает цвет сохранённой старой темы.

`ClientPreferences` сохраняет версию JSON 1, добавляет необязательное поле `accentHex`. Старые `theme`, рамки и прочие параметры сохранены. Отсутствующее, ошибочное или неверно типизированное новое поле игнорируется без сброса остальных настроек. Неизвестные поля сохраняются существующим механизмом. Используется прежняя атомарная запись с `.bak`.

Цвет используется в заголовках меню/настроек, кнопке «Играть», применении HEX и активных вкладках листа. Для заголовков акцент осветляется при необходимости; текст основной кнопки выбирается чёрным или белым, включая hover/focus. Расчёт контраста использует sRGB/WCAG, порог 4.5:1; для заголовков учтена верхняя оценка яркости прозрачных панелей поверх обоев. Семантические роли `UiStyleRoles` подготавливают основные/второстепенные панели, карточки, вкладки, кнопки, ввод, заголовки, подписи и индикаторы. Это небольшое сопоставление существующих GUIStyle, без отдельной системы тем.

Цвета, основные размеры и параметры девятисегментных фонов находятся в `UiTheme`. Значения размеров существующего листа не уменьшены. Кэш сравнивает исходные значения настроек до разбора цветов. Текстуры/skin создаются только при инициализации или инвалидировании. Исходный skin хранится отдельно, восстанавливается перед уничтожением сгенерированного skin; зависимые стили очищаются. Владение текстурами остаётся в `brandStyleTextures`.
