# Способности и магия — план визуального клонирования (15.11.2026)

**Репозиторий:** waitermisanthrope-creator/DnD-VTT
**Ветка:** `experiment/unity-vtt` (не менять `main`).
**Baseline при аудите:** `57897d827f77ffaa0af860bfeb05c0e9f9ad203c`.
**Эталон:** присланный владельцем коллаж, правый телефон; левый — концептуальная реконструкция.
**Текущее состояние:** реальный снимок владельца 691×1536; вертикальный IMGUI в `LegacySessionPanel.ClassicSheet.cs`.

## Обязательные принципы

- Интерфейсный клон: тёмный фон, золото, орнаменты, светящиеся табы/слоты, компактные карточки и нижняя навигация.
- У каждой способности и у каждого заклинания временная одинаковая квадратная заглушка `?`, пока арт-директор не утвердит индивидуальные изображения.
- Настоящие интерактивные IMGUI-контролы, только реальные данные из `hero`; никаких готовых скриншотов в подложке.
- Обработчики расхода — `CharacterSheetRules.ChangeAbilityUse/ChangeSpellUse/ChangePactUse/ChangeResource`; не менять правила и JSON-контракты.
- Подготовка заклинания — существующий `spellsData[].prepared`. Звёздочка обозначает именно её, **не новую механику «избранного»**.
- Отображать классовые `features` без выдумывания расходуемых зарядов или действия.
- Сохранять `ClearSheetInputs`, переключение разделов, свайпы, прокрутку и показ каталога `SpellCatalog`.
- Не трогать остальные вкладки; новая шапка и док должны применяться только к `sheetTab == 2`.

## Пошаговая реализация

1. Выделить `DrawGrimoireAbilities` в отдельный partial, оставить старую страницу как резерв для сравнения.
2. Шапка `СПОСОБНОСТИ И МАГИЯ` и две вкладки «Умения / Заклинания».
3. Фильтры умений (Все, Действия, Бонусные, Реакции). Неизвестные типы остаются в «Все».
4. Карточки умений `?` с названием, восстановлением, динамическими зарядами, расходом и возвратом, редактированием собственных приёмов.
5. Блок ячеек по кругам с живыми круглыми индикаторами, отдельным пактом, настройкой ячеек и нативными обработчиками.
6. Поиск и фильтрация заклинаний, каталог добавления.
7. Карточки заклинаний `?` с уровнем, временем, дистанцией, подготовкой-звездой и описанием.
8. Сохранить класс/ресурсы и характеристику атаки, поместив прежние настройки в сворачиваемый раздел.
9. Особая нижняя навигация только для страницы способностей: Герой, Инвентарь, Умения, Знания (существующий Лор), Настройки.
10. Проверка UI на Android/Windows, кадровое сопоставление с эталоном, итерации по видимым расхождениям.

## QA и ограничения

- Ручной визуальный контроль нужен на **реальной сборке**; одного source-diff недостаточно.
- Нельзя заявлять Unity compile/pass, Windows/Android UI, сохранение JSON roundtrip без реально выполненных проверок.
- Карточка заклинания не кастует магию автоматически: нынешний код поддерживает лишь подготовку/описание.
- Короткая кнопка «Применить» для приёма только расходует счётчик, не выбирает цель и не выполняет эффект.
- Блоки, отсутствующие в эталоне, допускаются лишь для сохранения ранее доступных действий.
- Пока изображения `?` — это намеренные заглушки, не окончательные иконки.
- Результат оценивается по скриншоту эталон/реальный APK и по нажатию на живые контролы.
