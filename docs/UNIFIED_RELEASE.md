# Один выпуск — Windows и Android

Статус: подготовлено и тестируется в ветке `windows-desktop`. Для использования кнопки выпуска workflow и Windows-оболочка должны быть перенесены в `main`.

## Что значит «одним действием»

В GitHub → Actions → **Unified Android + Windows release** → **Run workflow**:

- Ветка: `main`.
- `publish: true`.
- `version: auto` — увеличение patch (74.00.62 → 74.00.63); либо явно указанная версия.

Один запуск: записывает одинаковый новый номер версии в Android Gradle, JS-модуль обновлений и Windows package.json; коммитит и собирает из **одного SHA** Android debug + подписанный release APK, Windows Setup и Portable EXE. Проверяет хеши файлов, запускает тесты, публикует общий GitHub Release. Затем генерирует и активирует `updates/stable.json` с URL **неизменяемого исходного SHA**. Пока обе сборки не прошли — общая версия не рекламируется через OTA.

Перед использованием публикуемого режима важно, чтобы секреты `DND_VTT_KEYSTORE_BASE64`, `DND_VTT_KEYSTORE_PASSWORD`, `DND_VTT_KEY_ALIAS`, `DND_VTT_KEY_PASSWORD` были настроены как в существующей signed Android сборке. Иначе release *остановится*; debug APK не заменяет установленный signed APK.

`publish: false` запускает тестовые сборки без изменения номера версии, публикации, тега и OTA. При работе в ветке `windows-desktop` поддерживается только тестовый режим.

## Обновление из приложений

- Android: существующая кнопка/автопроверка читает общий манифест, скачивает SHA-256-проверенные файлы, атомарно переключает версию; ошибка запуска приводит к откату.
- Windows: тот же `app/update_manager_v2.js`, та же сцена загрузки, та же версия и тот же манифест. Electron native bridge проверяет пути, разрешённый источник, размеры и SHA-256, переиспользует совпадающие локальные файлы, переключает webroot и запускает приложение заново. При неуспешной проверке запуска откатывается.
- Персонажи и настройки на ПК остаются в профиле Electron (userData) и не удаляются заменой webroot. Автоматическая синхронизация сохранений между Android и Windows пока *не реализована*.
- **Ограничение:** общий OTA обновляет web-игру (классы, карты, 3D, CSS, JS, текстуры), но не native Java/Gradle или Electron main/preload. Для новых native функций после релиза нужно один раз установить новый APK или Windows Setup/Portable. Самоустановка EXE обновлений пока не реализована.
- Первая Windows-сборка без `desktop/update.cjs` сама не сможет получить OTA. Нужно перейти на новую Windows-сборку с native bridge, после чего web-обновления смогут устанавливаться внутри приложения.

## Что важно для безопасного выпуска

- После переноса на `main` старый workflow `Refresh in-app update manifest` перестаёт публиковать обновления, чтобы не обходить проверку обеих платформ.
- GitHub Pages копирует **утверждённый** `updates/stable.json`, а не генерирует преждевременную версию.
- Манифест включает root GLB, MP3 (через ambience), legacy обои и PNG. Новый номер версии не выпускается при неполном наборе ресурсов.
- Релиз выполняется **только вручную**, а тестовые сборки могут запускаться на ветке.
- Если выполнение прервалось до этапа публикации манифеста, уже установленные приложения продолжают использовать предыдущую утверждённую версию. Повторный запуск после частичного выпуска может потребовать проверки существующих тегов и релизов.

## QA перед первым пользователем

Проверить Windows Setup и Portable: запуск, обновления из настроек и после заставки, сохранения после релонча, редактирование персонажа и карт, локальную базу данных. Проверить APK на реальном Android с существующей подписанной установкой. Проверить вручную откат на ошибочном веб-пакете.

Не объявлять систему полностью проверенной до этих живых тестов. Код и тестовая CI-сборка не доказывают работоспособность каждого устройства.
