# Unity: постоянные правила разработки

Область — `unity/`; вместе с корневым `../AGENTS.md`. Работать исключительно в
`experiment/unity-vtt`: перед записью проверить `git branch --show-current` и
`git status --short`. Не переключаться на main, не сливать, не публиковать релизы.
Не менять секреты, ключи, GitHub Actions и не подключать платные сервисы без поручения.
MMO — WAIT_TEAM; не внедрять MMORPG и не переставлять общую очередь задач.

## Короткий старт и архитектура

Прочитать актуальные начала `../AI_NEXT_TASK.md`, `../AI_PROGRESS.md`,
`../AI_BLOCKERS.md`; затем нужные разделы `../PROJECT_ATLAS.md`,
`../00_AI_PROJECT_GUIDE.md`, `../01_plansforproject.md` и исходники/вызовы/проверки
затронутого модуля. Не загружать целиком исторические документы и не копировать атлас.
Текущий код определяет фактическую архитектуру; ограничения миграции —
`../docs/UNITY_CHARACTER_SHEET_PARITY.md`, контекст — `../docs/UNITY_MIGRATION_PLAN.md`.
Исторические статусы сверять с текущим кодом и compact state.

- Основная сцена: `Assets/Vtt/Scenes/ImportedAdventure.unity`; `Exploration.unity` — регрессия контроллера.
- `Assets/Vtt/Runtime/LegacySessionPanel*.cs` — существующий partial UI;
  `LegacyDocuments.cs`, `CharacterSheetRules.cs`/`CharacterSheetStore` — документы и сохранение;
  `CharacterCreation.cs`, `CharacterFiles.cs`, `ClientPreferences.cs` — создание, файлы, настройки.
- `LegacyMapPresenter.cs`, `ExplorerController.cs` — карта/движение;
  `DiceTable*.cs`, `WorkshopStore.cs`, `CloudCharacterProtocol.cs` — существующие подсистемы.
- `Assets/Vtt/Editor/`, `ci/`, `verify.ps1` — проверки/сборки;
  `Tools/` — синхронизация, `Assets/Plugins/Android/` — нативные мосты.

Расширять существующие компоненты, не создавать параллельные stores/механики.
Не подменять рабочую механику заглушкой и не выдавать существующий placeholder
или неполный порт за реализацию. Неподдерживаемые действия обозначать явно.
Версии брать из `ProjectSettings/ProjectVersion.txt` и `Packages/`; не обновлять попутно.
Перед UI-кодом применять Unity UI skill; существующий OnGUI — `unity:ui-imgui`.
Использовать релевантные Superpowers и Unity Plugin Skills, если они доступны;
их отсутствие сообщить, не имитировать вызов и не устанавливать сервисы автоматически.

## Данные и платформы

Сохранять неизвестные JSON-поля, wrapper, остальных героев, ID и legacy-контракты;
никаких слепых переименований HP/resources/classFeaturesState и потери состояния.
`dnd_multi_characters_v2.json`, атомарная запись, `.bak` и восстановление обязательны.
Для QA только синтетический отдельный `--vtt-profile-store <absolute-json-path>`;
не перезаписывать реальные профили. Миграция требует чтения старых данных,
roundtrip/restart/backup и безопасного отказа при ошибках/конфликте ID.

Поддерживать Android и Windows в одном Unity-проекте; проверять нативные мосты,
touch/mouse, lifecycle, пути и IL2CPP по области изменения. Не перенаправлять Unity
в старые android/desktop WebView. Сохранять `.meta` и GUID при перемещениях,
проверять ссылки сцен/префабов. Не запускать Setup/MigrationSetup ради проверки:
они пересоздают сцены; сначала сохранить ручные изменения и проверить diff.

## Экономный процесс и завершение

Простая задача — один Codex. Сложная — максимум два встроенных субагента на первом
этапе: Explorer (архитектура, только чтение) и QA (тесты/риски, только чтение).
Параллельно только независимые области; выдать каждому цель, пути, запрет записи
и короткий формат отчёта. Дождаться обоих отчётов перед реализацией. Основной агент
сверяет исходники и реальные результаты. Не давать агентам одновременно писать
одни файлы; при дальнейшем делегировании явно разделять владение файлами.
Не создавать лишних ролей и не дублировать Superpowers. `.codex/agents/` использовать
только после подтверждения документированной поддержки и проверки в текущем Cloud.

После этапа — быстрые целевые проверки, не весь набор после каждой мелкой правки.
Для исправлений добавлять проверку наблюдаемого дефекта/контракта; документация
не требует искусственных игровых тестов. Перед интеграцией важных изменений —
полная релевантная регрессия, включая сохранения и обе платформы при изменении
сериализации/сборки. Команды и ограничения: `../docs/UNITY_AGENT_WORKFLOW.md`.

Готовность: требования покрыты, diff проверен, тесты выполнены с exit code/результатом,
ограничения перечислены. Сборка успешна только после фактического выполнения;
контрактные тесты не доказывают компиляцию, runtime, графику или физический Android.
Отчёт: файлы, проверки, оставшиеся риски. Свидетельства — `VALIDATION.md`, актуальные
`../docs/unity-account/` и `../docs/unity-account/USER_AUDIT_1.00.40.md`.
