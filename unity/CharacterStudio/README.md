# DnD VTT — Character Studio, первый этап переноса в Unity

Самостоятельный нативный предпросмотр человеческой базы из существующего WebView.
Это начало переноса редактора персонажа, не перенос всей VTT и не новая версия
Android/Windows-приложения. Старое приложение и его сохранения продолжают работать.

## Как открыть

1. Установить Unity Hub и Unity **6000.0.23f1 (Unity 6)**. Для дальнейших сборок
   выбрать Windows Build Support и Android Build Support с SDK/NDK/OpenJDK.
2. В Unity Hub: **Add → Add project from disk**, выбрать эту папку
   `unity/CharacterStudio` (папку с `Assets`, `Packages`, `ProjectSettings`).
3. Дождаться загрузки пакетов URP/Newtonsoft и импорта FBX. Нужен доступ к Unity
   Package Registry. При первом импорте автоматически создаются настройки URP.
4. Выбрать **DnD VTT → Open Character Studio**, затем нажать **Play**.
   Сцена строит камеру, свет и модель при запуске. До Play Scene View почти пуст.
5. Если настройки рендера потерялись: **DnD VTT → Prepare Character Studio**.

Управление: перетаскивание модели мышью/пальцем — вращение, колесо/два пальца —
масштаб. Кнопки «Тело», «Лицо» и ракурсы управляют камерой. В вертикальном окне
панель располагается снизу. «Серый материал» позволяет оценивать форму без кожи.

Проверка импорта в самом Unity: **DnD VTT → Validate Character Assets**.
Тесты: **Window → General → Test Runner → EditMode → Run All**.
Ожидаются пять тестов: сохранность JSON, отказ от неподдерживаемых рас,
отказ от некорректных параметров, импорт ассета, конечная геометрия обеих форм
при противоположных крайних настройках. Последний тест не доказывает красоту
или отсутствие самопересечений — это отдельная визуальная проверка.

## Что перенесено

- Настоящий FBX с исходным скелетом (53 кости), UV и 107 024 треугольниками.
- Все 23 исходных морфа, включая `human-female` и 14 дополнительных targets.
- 15 осей тела: 11 каналов морфов и перенос процедурных height/width/muscle/fat.
- Две исходные текстуры кожи и простой URP Lit материал.
- Студийное освещение, камера, мужская/женская формы, серый материал.
- Простой нативный IMGUI-интерфейс для первой проверки на ПК и телефоне.
- Импорт/экспорт `appearance3d` schemaVersion 2, в том числе внутри одного листа
  персонажа. Неизвестные поля сохраняются в исходном JSON-дереве.
- Отдельный локальный черновик в `Application.persistentDataPath`.

Морфы применяются через SkinnedMeshRenderer, затем тело запекается при изменении
параметров для процедурных деформаций и отображается обычным MeshRenderer.
Скелет сохранён в ассете, но живой анимационный контроллер ещё не перенесён.
Это статический редактор: кнопки поз, речь и бой будут отдельным этапом.
Морфы обновляются при изменении внешности; постоянного пересчёта сетки каждый
кадр нет. Алгоритм сглаживания нормалей в этой версии приблизительный.

Простое бельё создаётся из участков поверхности тела и служит только прикрытием
в предпросмотре. Это не экспорт старого гардероба и не готовая система одежды.
Границы белья могут быть ступенчатыми. Ползунки сохраняют прежний диапазон:
крайние комбинации не гарантируют красивой анатомии.

## Как перенести конкретного персонажа из WebView

Сначала сохранить внешность в старом редакторе. В консоли разработчика старого
приложения можно получить JSON без изменения сохранений:

```js
JSON.stringify(currentChar.appearance3d, null, 2)
```

Скопировать полученный JSON в Unity через **Импорт / экспорт JSON → Применить**.
Допускается также JSON одного целого листа персонажа с полем `appearance3d`.
Массив всех персонажей и облачные учётные данные сюда импортировать не нужно.

Этот этап принимает только `human` и `human_variant` и пол `male`/`female`.
Другие расы отклоняются с сообщением, а не подменяются человеком. Поля лица,
одежды, анатомии, поз и дополнительные поля листа сохраняются, но пока не
визуализируются. Базовая кожа выбирается по полу; пользовательские skinId,
тонировка и расовые материалы пока не отображаются.

Сохранение пишет только отдельный Unity-черновик. Здесь нет синхронизации с
localStorage, Supabase или исходным списком персонажей. Вернуть JSON можно через
копирование, но автоматическая обратная запись в WebView не реализована.

## Воспроизводимый экспорт ассетов

Из корня репозитория, Blender 4.3.x:

```bash
blender --background --python-exit-code 1 --python tools/unity/export_character.py
```

Экспортёр проверяет хеши базовых координат и sparse-морфов, собирает временный
GLB, экспортирует FBX и повторно импортирует его в Blender. Проверяются кости,
треугольники, имена морфов, размер и непустой женский target. `MorphCatalog.json`
содержит хеши исходников, результат и каналы параметров. FBX и текстуры уже лежат
в проекте: Blender для обычного открытия Unity не требуется.

Исходники остаются в `app/assets/3d/makehuman`. Текстуры скопированы без изменения;
сохранена `LICENSE.ASSETS.md`. Это существующие ассеты проекта, сторонние моды
не добавлялись.

## Что ещё нужно сделать

1. Открыть и проверить проект в настоящем Unity Editor, выполнить EditMode-тесты.
2. Сравнить обе модели в сером материале и с кожей, подтвердить ориентацию,
   масштаб, ракурсы, переходы форм и соответствие параметров WebView.
3. Проверить интерфейс и скорость изменения сетки на Windows и Android.
4. Доработать анатомию, глаза/веки, кожу и волосы, затем скелет и анимации.
5. Переносить расы, гардероб и связь с листом по отдельным проверяемым этапам.

**Честный статус проверки:** экспорт/повторный импорт Blender проверены в среде
разработки. Unity Editor в этой среде отсутствует: компиляция C#, рендер URP,
Unity-тесты, Windows/Android-сборки и физические устройства пока не проверены.
Новые APK/EXE не выпускались. Внешний вид уровня BG3 этим переносом не создан.
